## Phase Goal

> Same derivation as plan 01: the ROADMAP goal is not in user-story format, so it is restated, not invented. **As a** platform engineer, **I want to** have every boot-time configuration contract fail fast with a named error, **so that** a misconfigured process never starts in a half-valid state.

<objective>
Turn configuration into a boot contract. The tracer proved one config value; this plan makes the whole
env surface Zod-validated with a named failure, adds the two-Redis discrimination that keeps the
cache/queue split from silently regressing, and establishes the two ioredis connection profiles with
the correct `maxRetriesPerRequest` split and no `keyPrefix`.

Purpose: FND-09 and the D-12/D-14 rulings are the kind of commitment that is cheap now and a production
incident later; the boot-time named failure is also what makes every later phase's misconfiguration
diagnosable.

Output: a validated config module, a distinct-host Redis refinement, and two connection profiles with
the BullMQ prefix constant.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| process env → config module | Environment values are untrusted input until Zod validates them. |
| config → Redis clients | A single-instance Redis silently violates the durability split; an evicting policy on the queue loses jobs. |
| request path → Redis | An unbounded retry hangs the HTTP handler. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-1-04 | Spoofing | `AppConfigSchema` / boot hook | high | mitigate | `.strict()` + named `CONFIG_INVALID:` failure; unknown or missing keys abort boot before any provider instantiates (FND-09). |
| T-1-05 | Tampering | `redis.schema.ts` distinct-host check | high | mitigate | `superRefine` on `new URL(...).host` with `REDIS_INSTANCES_NOT_DISTINCT`; a logical-DB suffix cannot satisfy it (D-12). |
| T-1-06 | Denial of Service | `redis.provider.ts` producer profile | medium | mitigate | Finite `maxRetriesPerRequest` on the request path so a downed Redis returns an error instead of hanging the handler (D-14). |
| T-1-SC | Tampering | npm installs | high | mitigate | `ioredis@6.0.0` is in `STACK.md §14`; no new package is introduced by this plan. |
</threat_model>
