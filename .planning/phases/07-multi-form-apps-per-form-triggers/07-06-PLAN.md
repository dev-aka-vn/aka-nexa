The App Builder's Forms tab becomes a **form manager**: list the app's forms one row per form,
add by kind (only unclaimed kinds, `submit` required to publish), remove with the confirmed
destructive flow, and launch the per-form designer. The mockup's `tabForms` layout is the source
of truth (rows, CTA, Versioning card, FormIO accent callout); the six U-1…U-6 rulings from
07-05-SUMMARY.md decide the undepicted parts (kind picker, remove confirm, row metadata).

Purpose: D-12 — this is the builder-facing half of "an app is a container of forms"; the
app-level Triggers tab is already retired (07-02).
Output: `FormManager.tsx`, the editor wiring, e2e coverage, and the submission-survival
integration assertion.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| builder SPA → app-builder API | Add/remove form PATCH payloads cross here (owner-session authenticated) |
| forms[] patch → submissions store | A definition mutation must not cascade into submission data |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-14 | Tampering (data loss) | remove-form flow cascading into submissions | high | mitigate | The remove flow writes ONLY the `forms` section (S3's one-section-one-field makes a cascade structurally impossible); the survival integration test is the wired check, and the U-4 modal copy states the guarantee to the user. |
| T-07-15 | Elevation of Privilege | manager PATCHes bypassing section permissions | medium | mitigate | The manager saves through the same `{section:'forms'}` PATCH as the Phase-6 editor — `assertOwner` + the BLD-03 `forms`-section ability check apply unchanged; no new permission surface is introduced (asserted by the existing app-builder module specs staying green). |
| T-07-16 | Denial of Service (author-side) | removing the last submit form silently stranding the app | low | mitigate | The U-4 ruling decides blocked-or-warned in the SPA; the publish gate (07-08) blocks publish with a named reason regardless — the author can never silently ship an unpublishable state. |
| T-07-SC | Tampering | npm/pip/cargo installs | high | mitigate | Zero packages installed; any discovered need runs the package-legitimacy gate first. |
</threat_model>
