<objective>
Deliver LNK-02: an owner-only edit link on the frozen `edit` action that can be reopened repeatedly, consumes on submit, expires after a configurable TTL (default 4 hours), and returns the original confirmation on a second submit (SC#4). The consume is atomic, and a submitted edit is a new revision with a new send.

Purpose: SC#4 — the edit link is the user-facing half of the per-revision outbound model; a non-atomic consume or a duplicated revision here is a silent downstream double-write.
Output: the `edit` verifier branch, an atomic one-time token store with an outcome key, the edit controller path, and their proofs.
</objective>

<assumption_delta_decision>
Assumption-delta signal: `{kind: pluralization, term: "second"}` (from SC#4's "…a second submit returns the original confirmation…"). This plan owns the replay semantics the term refers to. The noun that is now primary is **revision** (`{submission_id, revision}`); "second" denotes a re-delivery of the *same* revision's already-consumed link, not a new entity and not a new revision. Decision: **no-change** — no new noun or entity is promoted; the D-95 replay returns the confirmation recorded at consume time for the same `jti`, and D-91 keeps a genuinely new correction a *new revision with a new send*. (The tracer recorded the same decision in 05-01; this plan is the one that implements it.)
