# Phase 06 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

> **RETROACTIVE CONTRACT.** Phase 06 was already executed (8/8 plans, in verification) when this
> contract was written. Every value below is **documented from the shipped SPA**
> (`apps/app-builder/src/`) and its design authority (`prototypes/mockup.html`), **not invented**.
> Where the shipped build diverges from the authority, the divergence is recorded as an
> **observed divergence** (see `06-UI-REVIEW.md`) — it is a follow-up, not the contract.

## Design System

| Property | Value |
|----------|-------|
| Tool | none |

| Component library | none — hand-rolled React 19 components over the ported mockup stylesheet (`tokens.css` + `chrome.css`) |

callouts, drawers, toasts, step-rail, kv lists, `od-*` layout primitives). No `components.json`
exists and no third-party registry is declared, so no registry vetting gate applies.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, tight row gaps |
| sm | 8px | Compact element spacing — the token default (`--od-gap: 8px`) |
| md | 16px | Default element spacing; rail padding (`--od-rail-pad: 16px`) |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps, empty-state inner padding |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing (view bottom padding) |

Exceptions:
- **Mockup-verbatim values that are not multiples of 4 are part of the design authority and are
  declared, not defects:** card-body padding `18px`, page-head `gap: 18px`, desktop `.view`
  padding `26px 28px 64px`, ≤960px `.view` padding `20px 16px 60px` (`chrome.css:135,380`).
- **Observed divergence (06-UI-REVIEW Pillar 5):** the shipped SPA overrides `--od-gap` 39 times at
  off-grid values (`10px`×16, `12px`×4, `14px`×3, `18px`×4, `6px`×2, `4px`×1) and overrides `.view`
  to a **third** padding (`20px 22px 60px`, `App.tsx:570`) matching neither the mockup's desktop nor
  its breakpoint value. `~130` inline `style={{}}` objects bypass the class vocabulary. This is a
  recorded consolidation follow-up, not the contract.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.55 |
| Label | 11.5px | 600 | 1.3 |
| Heading | 15.5px | 600 | 1.25 |
| Display | 25px | 600 | 1.15 |

Roles resolve through the ported class system, not inline styles: Body = `IBM Plex Sans` 16/1.55;
Label = uppercase `thead th` / nav-label / field label at 11.5px, weight 600; Heading = `card-head
h2/h3` at 15.5px; Display = page `h1` at 25px — both Display and Heading in `Space Grotesk` 600.

Exceptions:
- Stat value `.stat .v` renders at **29px** (Display tier); mono cells (`.cell-mono`, `.pill-mono`,
  `.code-inline`) render at **12.5px** (`IBM Plex Mono`).
- Weights **500** (medium — ported buttons/tabs) and **700** (bold — emphasis) appear in
  `chrome.css`; the two declared contract weights are 400 + 600.
- **Observed divergence (06-UI-REVIEW Pillar 4):** ~40 inline `fontSize`/`fontWeight` overrides
  introduce 9 distinct sizes (11, 11.5, 12, 12.5, 13, 13.5, 14, 16, 17) and duplicate the class
  system (e.g. a card title is 15.5px in one place, 16px in another). Consolidation follow-up.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f6f8fa` (`--canvas`) + `#ffffff` (`--surface`) | Page background, cards, tables, drawers |
| Secondary (30%) | `#0e1420` (`--ink`) | The mockup's dark sidebar/nav anchor (`--ink-2 #151d2e`, `--ink-3 #1e283c` for its tiers) |
| Accent (10%) | `#0f9d8f` (`--accent`) | See the reserved-for list below |
| Destructive | `#c0392b` (`--red`, `--red-soft #fdecea`) | Destructive/error actions and error callouts only |

Accent reserved for: **primary buttons** (`.btn-primary` — e.g. `Create app`, `Publish`, `Save
role`); **focus rings** (`:focus-visible { outline: 2px solid var(--accent) }`); **links**
(`a { color: var(--accent-strong) }` = `#0b7d72`, `--accent-soft #e4f5f2` for tinted surfaces);
**selected tab** (`.tab[aria-selected]`); the **progress meter fill**; and the **selected
`radio-card`** (`.radio-card.sel`). Never used as decorative fill or as a status colour.

Semantic status scale (not part of the 60/30/10): `--green #2f855a`, `--amber #b7791f`,
`--red #c0392b`, `--blue #2b6cb0`, `--violet #6b5bd2`, each with a `-soft` background variant.
Lifecycle badge vocabulary follows the mockup's `statusBadge()` (`mockup.html:782-790`):
**published = green** (`badge-published`), **draft = neutral** (`badge-draft`),
**deprecated = amber** (`badge-deprecated`), **archived = violet** (`badge-archived`)
(`chrome.css:192-196`).

Exceptions:
- **Observed divergence (06-UI-REVIEW Pillars 2–3):** the shipped shell omits the mockup's dark
  `--ink` sidebar (it renders a light top button row), so the rendered 60/30/10 has **no dark
  anchor**; and the badge tone mapping shipped inverted-can be corrected against the vocabulary
  above. Zero hardcoded colours exist in TSX — every colour resolves through `var(--*)`.

## UI Considerations

> Populated by the ui-phase UI-consideration probe (Step 9.5) and lifted by plan-phase's
> `## UI Considerations` lift rule via the identical rule as SPEC `## Edge Coverage`. Shape-rooted UI *state*
> coverage (empty / loading / error / populated / partial / overflow / zero-one-many / long-text).
> Empty-state and error-state COPY live in `## Copywriting Contract` above — this section covers
> state coverage and REFERENCES those rows rather than restating the copy (de-dup).

Applicable state considerations resolved: 5 covered, 2 backstop, 1 unresolved

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | list-collection | ✅ covered | Every list renders a tailored empty state (apps, gallery, submissions, audit, transfer queue, connector requests, SSO mappings) — see `## Copywriting Contract`. |
| loading | async-surface | ✅ covered | Every async read shows a layout-shaped `Skeleton` (`text`/`cards`/`block`), never a spinner-only blank (BLD-09); each dashboard widget loads independently. |
| error | async-surface | ✅ covered | Every async failure renders an inline, specific, retryable `InlineError` in the content slot (BLD-07); dashboard widgets fail isolated without killing the other widget. |
| partial | data-surface | ✅ covered | Dashboard widgets load/fail independently; the editor saves and publishes per-section, so a partial definition stays usable. |
| disabled | action | ✅ covered | Publish and section-save disable while `saving`; transfer approve/reject while `acting`; template fork while `forking`; undo/redo disabled at history ends. |
| zero-one-many | list-collection | 🧪 backstop | Tables render the same shape for zero/one/many; the dashboard caps each widget at 5 rows; audit and submissions paginate by offset. No hold-out test asserts the one-row or last-page edge. |
| long-text | static-content | 🧪 backstop | Table cells rely on layout wrap, not CSS ellipsis; long app names / base URLs in the connector table have no held-out visual test. |
| overflow | container | ⚠ unresolved | 10 of 12 editor sections are a raw `<textarea rows={14}>` of hand-edited JSON (`editor/EditorPage.tsx:59-61,646-653`); long payloads scroll with no structured overflow handling. Planner treats as an assumption. |
