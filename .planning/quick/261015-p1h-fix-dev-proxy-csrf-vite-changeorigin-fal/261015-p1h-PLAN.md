<objective>
Make every mutating request from the App Builder SPA succeed against the real API in the dev stack.

Today a browser at `http://127.0.0.1:5173` sends `Origin: http://127.0.0.1:5173`, but the Vite dev proxy's `/api` entry sets `changeOrigin: true`, which rewrites the forwarded `Host` to the target's (`127.0.0.1:3000`). The API's CSRF gate compares `new URL(origin).host` against `req.get('host')` (`apps/api/src/auth/session.middleware.ts:102`), sees `127.0.0.1:5173 !== 127.0.0.1:3000`, and refuses with 403 `CSRF_ORIGIN_MISMATCH`. Every write from the SPA is affected — create app, fork template, save section, publish, deprecate, archive, and logout. Reads are `GET`, so the SPA merely *looks* half-functional.

Purpose: the API observed to be correct (direct-with-matching-Origin → 201) and the proxy observed to be wrong (proxied → 403) means the defect is a one-line dev-configuration error, not an application bug. The gate is the frozen T-06-04 / D-101 contract; it stays exactly as written.

Output: a Vite config whose proxy preserves the browser's Host, a `/auth` entry plus documented dev redirect URI that makes the OIDC callback land on the SPA origin, and one deterministic `tooling/` spec that fails if a Host rewrite is reintroduced.

**Quick task, not a ROADMAP phase:** `requirements` is intentionally empty. The work serves the already-Complete BLD-12 / D-101 surface, but it adds no requirement coverage — it repairs the developer path to it.
</objective>

(a) Add an `/auth` entry to `server.proxy`: `target: API_ORIGIN`, `changeOrigin: false`, and **no `rewrite`**. Explain in the config comment why the two entries differ: callers address the API as `/api/...` (hence that entry's rewrite), whereas `/auth/...` is already the API's own path — the OIDC routes are mounted at the root — so a rewrite there would corrupt the path.

Why the entry is needed (`apps/api/src/auth/oidc.service.ts`): `begin` signs the authorization request with the **configured** `redirect_uri` (line 382), while `callback` **re-derives** it from the live request as `new URL(\`${req.protocol}://${req.get('host')}${req.originalUrl}\`)` (lines 411-413). The stub issuer rejects a token exchange whose `redirect_uri` differs from the one issued. With the Host preserved the derived value is `<spa-origin>/auth/oidc/callback`; without the `/auth` entry that callback never reaches the SPA. So: config names the SPA origin, `/auth` is proxied, and the same-origin shape the production build has.

(b) `.env.example`: keep the uncommented production example value exactly as it is (`OIDC_REDIRECT_URI=https://api.example.com/auth/oidc/callback`) — in production the API serves the SPA same-origin, so the API origin is right.
