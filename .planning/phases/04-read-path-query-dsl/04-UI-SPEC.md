# Phase 04 — UI Design Contract

> Visual and interaction contract for the Phase 4 read path: the view page, the server-paginated
> query-results table, and the dead-link denial page in the FormIO renderer. Generated by
> gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Design system source:** `components.json` is absent — there is no shadcn. The project's design
> system is the **custom CSS `:root` token set** defined in `prototypes/mockup.html` (lines 47–84).
> Per AGENTS.md, Phase 4 read surfaces are **not depicted** in the mockup; this contract reuses
> **only the token set** (colours, typefaces, spacing, radius, shadows) — no new palette or
> typography is invented. The renderer (`apps/renderer`) is a greenfield placeholder (9-line
> `index.html` + `prefill.ts`); Phase 4 scaffolds it as a Vite 8 + React 19 single-page app that
> imports the mockup's tokens and renders three new pages.

## Spacing Scale

Declared values (multiples of 4; mockup baseline `body { font-size: 16px }` + `--od-gap: 8px`):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding in compact cells |
| sm | 8px | Default element spacing (`--od-gap`), table cell internal gaps |
| md | 16px | Section padding, card body padding, table cell horizontal padding (16px per mockup `td`) |
| lg | 24px | Page section padding, major content-block gaps |
| xl | 32px | Layout gaps between major sections |
| 2xl | 48px | Major section vertical breaks |
| 3xl | 64px | Page-level vertical rhythm |

Exceptions: **44px minimum touch target** (`--od-touch { min-width: 44px; min-height: 44px; }`)
applies to the dead-link page's "Request a new one via IM" link/button and all clickable elements
on read surfaces. Table cell horizontal padding is 16px and vertical is 13px (from mockup
`tbody td { padding: 13px 16px }`).

## Typography

Using mockup typefaces only: `--display` = Space Grotesk, `--sans` = IBM Plex Sans,
`--mono` = IBM Plex Mono. Exactly 2 weights, matching the mockup's `h1,h2,h3,h4 { font-weight: 600 }`
and `body { font-weight: 400 }`:

| Role | Size | Weight | Line Height | Font |
|------|------|--------|-------------|------|
| Display | 25px | 600 | 1.2 | Space Grotesk (`--display`) — page `<h1>` |
| Heading | 16px | 600 | 1.3 | IBM Plex Sans (`--sans`) — section sub-headings |
| Body | 14px | 400 | 1.55 | IBM Plex Sans (`--sans`) — paragraph text, table cells |
| Label | 12.5px | 600 | 1.4 | IBM Plex Sans (`--sans`) — table column headers, field labels, captions |

Notes:
- **View page**: `@formio/js` read-only mode (D-68) renders field labels and values in
  FormIO's Bootstrap-5 typography (S1 spike). Page chrome (submission title, metadata line,
  surrounding paragraph) uses the tokens above (Display 25px, Body 14px).
- **Query table**: column headers at 12.5px, uppercase, letter-spacing 0.06em (mockup
  `thead th` is 11.5px; 12.5px selected for clean token alignment with `.helper` / `.stat .k`
  usage). Body cells at 14px (mockup `table { font-size: 14px }`).
- **Dead-link page**: heading at 25px Display; denial message at 14px Body; CTA link at 14px Body
  in `--accent-strong` colour.
- `--mono` (IBM Plex Mono, 12.5px) is used for: submission IDs, query IDs, `jti` values in audit
  context, and any code-like string displayed on read surfaces.

## Color

All values from mockup `:root` (lines 47–69).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--canvas` #f6f8fa | Page background for all three read surfaces |
| Secondary (30%) | `--surface` #ffffff / `--surface-2` #f0f3f7 | Table background (`--surface`), row hover (`--surface-2`), card backgrounds |
| Accent (10%) | `--accent` #0f9d8f | Reserved for: focus ring (`:focus-visible { outline: 2px solid var(--accent) }`), the "Request a new one via IM" link on the dead-link page, active pagination page, row hover background (`#fafcfe`), link colour |
| Destructive | `--red` #c0392b | Denial/error state text and icons on the dead-link page; invalid link borders |

Accent reserved for: focus rings on interactive elements, the "Request a new one via IM" link
on the dead-link page, active/selected pagination states, and links. Not used for static
decoration or non-interactive text. Red is used only for denial states (expired, revoked,
bad_signature, deactivated_user) — not for success or neutral content.

## Copywriting Contract

All copy follows the existing `LinkErrorFilter` precedent
(`apps/api/src/common/filters/link-error.filter.ts` lines 21–34) and the AGENTS.md voice:
clear, actionable, one sentence, ends with an IM affordance. Per D-70: "one sentence per reason,
sound like today's `LinkErrorFilter`."

| Element | Copy |
|---------|------|
| Primary CTA | "Request a new one via IM" (link on dead-link page and empty query state; minimum 44px touch target) |
| Empty state heading | "No results" |
| Empty state body | "There are no submissions matching this query." |
| Empty state action | "Request a new one via IM" (link) |
| Error state (query failure) | "Unable to load results. Please request a new query via IM." |
| Destructive confirmation | N/A — Phase 4 read surfaces have no destructive actions |

### Denial reason copy (LNK-08 × 7 + permission/not-found, D-70)

One sentence per reason. The 7th reason, **consumed**, is structurally impossible for read links
(audit note: `TOKEN_CLASSES.view.consume = false`, `TOKEN_CLASSES.query.consume = false` per
`token-classes.ts` D-42) but retained in the reason enum for the shared link-error model
(CONTEXT.md §"the agent's Discretion" reconciliation note). The server records the distinct reason
(LNK-08 via OTel counter with `reason` label, D-71); the UI displays the same reason with copy below.

| Reason (LNK-08) | Display copy | Action link |
|-----------------|-------------|-------------|
| expired | "This link has expired. Please request a new one via IM." | "Request a new one via IM" |
| consumed | "This link has already been used. Please request a new one via IM." (reserved — unreachable for view/query per D-42; included for shared-error-model completeness) | "Request a new one via IM" |
| revoked | "This link has been revoked. Please request a new one via IM." | "Request a new one via IM" |
| wrong_app | "This link is for a different app. Please request a new one via IM." | "Request a new one via IM" |
| wrong_version | "This link is for an outdated version. Please request a new one via IM." | "Request a new one via IM" |
| deactivated_user | "Your account is no longer active. Please contact your administrator via IM." | "Contact support via IM" |
| bad_signature | "This link is not valid. Please request a new one via IM." | "Request a new one via IM" |

Internal reasons (not in the 7, but rendered by the dead-link page per D-70 extension):

| Reason | Display copy | Action link |
|--------|-------------|-------------|
| denied (permission) | "Access denied. Your permission to view this app or record has changed." | "Request access via IM" |
| not_found | "This submission could not be found." | "Request a new one via IM" |
| not_owned | "You do not have permission to view this record." | "Request access via IM" |

## UI Considerations

Shape-rooted UI state coverage for the three Phase 4 surfaces. Empty-state and error-state copy
lives in `## Copywriting Contract` above; this section covers state mechanics and references those
rows. Resolved: 8 covered, 3 backstock, 1 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| {empty} | Query results table (0 rows after a successful query) | ✅ covered | Renders mockup `.empty` pattern: SVG placeholder + "No results" (16px) + "There are no submissions matching this query." (14px). Copy → `## Copywriting Contract` → Empty state. |
| {empty} | View page (submission not found / not owned) | ✅ covered | Does not render FormIO; renders dead-link page with `not_found` or `not_owned` reason. Copy → `## Copywriting Contract` → Denial table. |
| {loading} | Query table (DSL executing on server) | 🧪 backstop | 3 skeleton rows matching column count, shimmer animation on `--surface-2` background, table header visible throughout. Follows BLD-09 loading-skeleton directive. |
| {loading} | View page (JWT verify + submission fetch) | 🧪 backstock | Page chrome renders immediately (heading placeholder at 25px `color: var(--muted)`); FormIO container shows a 2000ms threshold spinner; below threshold, no spinner (avoid flash of loading). |
| {loading} | Dead-link page (JWT decoding only — no network call) | 🧪 backstock | JWT verification is synchronous (public-key `jose.jwtVerify`); display is immediate. A sub-100ms spinner only if the key fetch from JWKS is pending. |
| {error} | Dead-link page (all 7 + internal denial reasons) | ✅ covered | Reason-specific copy rendered inside mockup `.callout.callout-warn` container (amber soft background), CTA link below in `--accent`. Server OTel counter fires with `reason` label (D-71); UI reads the same reason from the verifier response. Copy → `## Copywriting Contract` → Denial table. |
| {error} | Query table (query execution failure, not a link denial) | ✅ covered | Inline message below the table: "Unable to load results. Please request a new query via IM." (mockup `.error-text` pattern, `--red` colour). "Retry" button at 14px. |
| {populated} | Query table (1+ rows, paginated) | ✅ covered | Columns from saved query projection; rows from DSL-compiled Mongo filter with injected `real_user_id` / `deleted_at: null`. Table follows mockup `.table-wrap` + `table` + `thead th` + `tbody td` patterns. |
| {populated} | View page (submission found, owned by `sub`) | ✅ covered | `@formio/js` read-only mode renders the FormIO schema (D-68). Single submission, structural invariant (D-79). |
| {partial} | Query table (fewer rows than total, `limit` cap reached) | ✅ covered | Footer row: "Showing {start}–{end} of {total}" at 12.5px `--muted`, with "Load more" button (`--accent`) when `offset + limit < total`. |
| {overflow} | Query table (long cell content) | ✅ covered | `td` text truncates with `max-width`, `overflow: hidden`, `text-overflow: ellipsis`, `white-space: nowrap`; full value visible via `title` attribute tooltip on hover. Table container scrolls horizontally on `< 768px` (mockup `.table-wrap { overflow-x: auto }`). |
| {zero-one-many} | Query table (0 / 1 / many results) | ✅ covered | 0 = empty state (above); 1 = single-row table; many = paginated table with "Load more". |
| {long-text} | View page (multi-line field values in FormIO) | 🧪 backstock | FormIO read-only renders `<textarea>` content with natural wrapping; max-height 200px with "Show more" toggle at 14px `--accent` when content exceeds threshold. |
| {mobile} | Query table (≤ 768px) | ⚠ unresolved | D-69 mentions "mobile fallback" but CONTEXT discretion leaves the exact pattern to the implementer. Recommendation: horizontal-scroll table on 769–1180px; stacked card-list on ≤ 768px (each row becomes a `.list-row`-style card with label/value pairs). Planner to confirm before implementation. |
