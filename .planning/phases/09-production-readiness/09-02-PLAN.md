<objective>
Deliver the audit read path and the erasure command: structured querying by user, app, action, and date range; JSON Lines export over the filtered set; an operator CLI erasure that tombstones the actor reference and purges the subject's submission bodies without removing a row; and a quarterly access-review report generated on a schedule and rendered in the console.

Purpose: This is the read-side half of the compliance story (ROADMAP success criteria 1, 2 and 3). Plan 09-01 made the trail durable and purgable; this plan makes it answerable. AUD-04 is the concrete encoding of conflict #2 — `actor_ref` is tombstoneable precisely because Phase 1 decoupled the trace ID from `submission_id`.
Output: Three domain services (query, export, erasure) plus the access-review generator, the `erase-actor` operator CLI, the extended audit HTTP surface, and two console surfaces (the rewritten Audit Log filters and the new Access Review route).

Q1 resolved: the **erasure path is its own named single owner** — `ActorErasureService`, separate from the retention sweep and the purge sweep delivered in 09-01, invoked only through the `erase-actor` CLI (D-07). Its guard test lives in this plan and asserts the survivor property; the retention guard test lives in 09-01 and asserts the cutoff property. Three owners, three guard tests, no shared "cleanup" primitive.

D-07 is honoured exactly: erasure is an **operator CLI command in `packages/cli`**, following the existing harness (`rebind.ts`, `provision.ts`), receiving a `real_user_id` and a ticket reference, and appending `erasure.executed` carrying that reference. It does not get a console button or an HTTP route — erasure is rare, deliberate and irreversible.

D-08 is honoured exactly: the erasure reaches **the audit refs AND the submission bodies**. `ProfileRepository` and `IdentityMappingRepository` are in-memory and therefore not durably erasable in this phase; that is recorded as a **named limitation** in the verification report (plan 09-07's or the phase verifier's output), never left as a silent gap.

D-11 is honoured exactly: **JSON Lines only**. `csv-stringify` is already a dependency and a CSV sibling would be cheap, but it is not built now — AUD-06's "CSV **or** JSON Lines" is satisfied by one format, and JSONL is lossless for the optional fields the trail carries.

D-09 is honoured exactly: `GET /audit` **serves `ip`**. The shipped projection is currently narrower than both the contract (`LOG_FIELD_ALLOWLIST` includes `ip` and `user_agent`) and the mockup (which renders an IP column), justified by a stale D-43 citation. This plan widens the projection to match the contract and corrects the stale comments in the same change. `user_agent` stays store-only.

D-10 is honoured exactly: `app_id` becomes a first-class entry field, fixing the second mockup-vs-contract gap (the audit table renders an **App** column that has no backing field).

The access-review schedule is a scheduled job in the same BullMQ Job Scheduler shape as 09-01's sweeps; do not use `@nestjs/schedule` (D-03/D-12). Its console route also offers the same JSON Lines download (D-12).

Do NOT promise full erasure of the audit record anywhere in code, copy, or comments. The narrowed promise is: Phase 1's log allowlist + this tombstone + 09-01's defined purge windows. The "legitimate interest" framing is a legal question, not a code comment.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| admin client -> audit query and export API | Authenticated admin input becomes a Mongo query predicate and a file download; both accept attacker-controlled strings. |
| erasure caller -> audit store | An erasure is irreversible mutation of the audit trail; the caller's authorisation is the only thing separating a compliance action from tampering. |
| scheduler -> worker queue | The quarterly generation trigger crosses a process boundary; the quarter must be derived inside the consumer, not trusted from the payload. |
| audit store -> export file | The export is a bulk egress of the full filtered trail; it is the highest-volume disclosure surface in the product. |
