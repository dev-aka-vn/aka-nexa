## Phase Goal

**As a** department admin, **I want to** build, secure, and publish a working app end-to-end, **so that** I need no engineering ticket and no platform admin's help.

<objective>
Close gap G-06-4: the publish action fires immediately from the button and from Ctrl/Cmd+S with no confirmation, and the shortcut publishes a section's persisted state while its JSON editor is mid-edit.

The gap's `root_cause` splits the two halves with different verdicts and this plan honours that split instead of flattening it. The mockup's *pre-publish modal with change rows* is a frozen-contract divergence: the change summary is defined as the publish *response* payload and the only route is `POST /apps/:id/publish`, with no dry-run endpoint — so a modal that lists rows before the POST cannot be restored without a new contract, and the contract wins (AGENTS.md precedence rule; 06-UI-REVIEW disposition #2). The *unsaved-changes guard* is a genuine defect and is fixed in full.

Purpose: the gap's truth has two clauses and both must hold — the action is confirmed before the change takes effect, and the Ctrl/Cmd+S shortcut cannot publish while a section's JSON is mid-edit. This plan delivers one explicit confirmation gate that both entry points route through (no rows, no new endpoint), and a dirty-JSON guard that blocks the chord while the active section's JSON differs from the persisted state.

Output: two pure guard predicates with their unit spec, the gate plus the dirty wiring in the editor page, and the publish coverage `editor.spec.ts` never had — the file has zero publish assertions today, which is the hole this gap shipped through.
</objective>
