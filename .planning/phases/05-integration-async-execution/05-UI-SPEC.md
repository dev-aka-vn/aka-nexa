# Phase 05 — UI Design Contract

> Visual and interaction contract for the Phase 5 user-facing surfaces: the **"My submissions"
> status list** (DAT-14), the submission **detail** (read-only FormIO re-use), the **`partial`
> read-only** presentation (D-81), and the **edit-link entry + post-submit confirmation**
> (LNK-02 / D-91…D-95). Generated by gsd-ui-researcher; verified downstream by gsd-ui-checker.
>
> **Design system source:** `components.json` and `tailwind.config.*` are absent — there is no
> shadcn and no React/Vite frontend package. The project's design system is the **custom CSS
> `:root` token set** in `prototypes/mockup.html` (lines 47–84) plus its class primitives. Per
> AGENTS.md the Phase 5 surfaces are **not depicted** in the mockup (which is the Phase 6 App
> Builder admin console); this contract reuses **only the token set and primitive classes** — no
> new palette, typeface, or visual language is invented. The renderer (`apps/renderer`) is a
> **plain HTML + TypeScript** app (not React/Vite); Phase 5 extends it in that same idiom.
>
> **Absence is not permission (AGENTS.md rule 3):** because the status surface and edit page are
> not in the mockup, every genuinely new interaction is stated as **newly specified here** and any
> truly open choice is marked **⚠ unresolved** rather than silently decided.
>
> **Operator-only (not UI):** the DLQ CLI (`dlq list` / `dlq retry`), connector upsert, and the
> `connector_ref` rebind (D-83/D-84/D-85/D-86) are **operator CLI** experiences in Phase 5. They
> must **not** appear as screens in this contract.

Using mockup typefaces only: `--display` = Space Grotesk, `--sans` = IBM Plex Sans, `--mono` = IBM
Plex Mono. Exactly **4 sizes** and exactly **2 weights** (matching the mockup's

## Surface & Interaction Contract

Four user-facing surfaces, all in `apps/renderer` (plain HTML + TypeScript), all reached from a
read-link URL (JWT in the URL, no cookie — FRM-06). URL idioms mirror the existing
`apps/renderer/src/read/view.ts` (`parseReadLinkUrl`) and the frozen six-action enum
(`create|edit|view|query|notification|draft`, `read-link-claims.ts`).

### A. "My submissions" status list (DAT-14, D-80)

- **Reached by:** the **frozen `query` read-link action** carrying a per-user saved query —
  `GET /l/query/{jti}?token=…`. No new token claim and no new action; DAT-11's auto-injected
  `real_user_id` + `deleted_at: null` is the ownership filter (D-80). **Per-app only** — cross-app
  listing is out of scope.
- **Shape:** `.page-head` (`h1` "My submissions" + `.sub`) over a `.table-wrap` + `table`.
- **Columns** (from D-82): **Form** (+ `v{form_version}`, `.cell-strong`) · **Submitted** (date,
  `--text-2`) · **Status** (badge) · **Destination** (phrase). Row actions are right-aligned
  (`.cell-actions`).
- **Status → badge → destination phrase** (newly specified here; the mockup `statusBadge()` map at
  `mockup.html:782` is the precedent for label text):

  | `Submission.status` | Badge (class → label) | Destination phrase |
  |---------------------|------------------------|--------------------|
  | `completed` (internal only) | `.badge-completed` → "Completed" (green) | "Internal saved" |
  | `completed` (external confirmed) | `.badge-completed` → "Completed" (green) | "{Connector} · {downstream reference}" (e.g. "Redmine · #4821") — reference shown to the user (D-82) |
  | `partial` | `.badge-partial` → "Partial" (amber) | "Internal saved · {Connector}: retrying" — **read-only, no retry control** (D-81) |
  | `pending_external` | `.badge-pending` → "Pending external" (blue) | "{Connector}: sending" |
  | `failed` | `.badge-failed` → "Failed" (red) | user-safe reason sentence (see Copywriting) — no raw HTTP body, credential, or PII (D-82) |

- **Row action — "Edit submission"** (owner-only, `.btn.btn-sm` / accent affordance): appears only on
  rows the user owns; issues/navigates to the edit link (D-93). Rows not owned show no action.
- **Filtering by status** (optional, newly specified): `.rail` of `.chip` buttons
  (`aria-pressed`) mirroring `mockup.html:1302`; pressed = `--ink`. This is a convenience only —
  the server-authored saved query is the source of truth.
- **Pagination:** server-side `.btn` "Load more" (accent) when `offset + limit < total`, with a
  "Showing {start}–{end} of {total}" footer in 12.5px `--muted`.

### B. Submission detail (reuses read-only FormIO rendering)

- **Reached by:** the **frozen `view` read-link action** — `GET /l/view/{jti}?token=…` — the
  existing `view.html` / `view.browser.ts` page, **extended** to surface status and destination.
- **Shape:** `.card` with `.card-head` (form label + `v{form_version}`), a metadata/status line, and
  a `.card-body` hosting `Formio.createForm(container, schema, { readOnly: true })` (as today in
  `view.browser.ts`). Field labels/values render in FormIO's Bootstrap-5 typography.
- **Status summary** above the form: status badge + destination phrase (same table as A) +
  submitted time.
- **`partial`** (D-81, newly specified): a `.callout.callout-warn` **above** the read-only form
  reading **"Internal saved · {Connector}: retrying"** plus one explanatory Body sentence. It is
  **read-only** — the detail page carries **no** "Retry" control. Retry stays with the admin/DLQ
  CLI (CON-04 / D-83–D-85). ⚠ Do **not** copy the mockup's admin drawer, which shows a "Retry
  external call" button (`mockup.html:1573`) — that is the admin surface, excluded for users.
- **`failed`**: a `.callout.callout-danger` with the user-safe reason (see Copywriting), plus a
  "Request a new link in chat" affordance where a fresh submission is the remedy.

### C. Edit-link entry (LNK-02, D-91/D-92/D-93/D-94)

- **Reached by:** the **frozen `edit` read-link action** — `GET /l/edit/{jti}?token=…`. Issued from
  the status list/detail **owner-only** (`real_user_id = sub`), with a **live app-permission +
  `perm_version` re-check on access** mirroring the view link (D-93); 4-hour TTL, consumes on
  submit (LNK-02).
- **Pre-fill:** from the **latest revision** (D-94) — the same `PrefillService` idiom
  (`apps/renderer/src/prefill.ts`) as the create form.
- **Shape:** `.page-head` (`h1` "Edit submission" + `.sub` naming the app/form and the revision
  number) over the FormIO form in editable mode; footer with `.btn-primary` "Submit correction" and
  a `.btn-ghost` "Cancel".
- **Denial on access** (expired / revoked / not_owned / denied / wrong_version): reuse the
  `dead.html` denial page and the `DENY_REASON_COPY` map in `view.ts` — no edit form is rendered.
- **Submit** creates a **new revision with a new send** (D-91); the downstream idempotency key is
  `{submission_id}:{revision}` (D-92). No inline editing of a committed revision — revisions are
  append-only (D-94).

### D. Edit post-submit confirmation (D-95, SC#4)

- **First submit:** the edit link consumes and renders a confirmation (`.card` + `.callout-accent` /
  success `.toast`) naming the new revision and, once confirmed, the downstream reference. The
  copy is the phase's success copy (see Copywriting).
- **Idempotent replay (SC#4):** a **consumed** edit link submitted a second time returns **the
  original confirmation** for the revision that consumed that `jti` — an idempotent replay: no new
  revision, no error, no duplicate record. The consumed-token path **branches by link action**:
  `create` → "already submitted"; `edit` → replay (D-95). The UI therefore shows the same
  confirmation card on replay, not the generic dead-link page.

### Interaction notes

- **No cookies, no session** (FRM-06); JWT travels in the URL. The status/detail/edit pages read the
  token exactly as `view.ts` does (query param or path segment).
- **No user-facing retry** anywhere on A/B (D-81). **No admin screens** (DLQ/connector management are
  CLI-only in Phase 5).
- **Focus and keyboard:** every interactive element shows `:focus-visible` (2px `--accent`, offset
  2px). Status-filter chips are a `role="group"` of `aria-pressed` buttons (mockup precedent).
- **Responsive:** reuse `.table-wrap` horizontal scroll on narrower widths. The ≤768px stacked
  `.list-row` fallback for the status list is **newly specified here** and ⚠ unresolved pending the
  planner's confirmation (same open point 04-UI-SPEC carried).

## Known Drift (existing surfaces — must NOT be inherited)

The shipped renderer surfaces predate this contract and **violate** the AGENTS.md rules. Phase 5
must **not** copy them; the existing pages should later be reconciled to this contract.

1. **Second palette (violates AGENTS.md rule 1).** `apps/renderer/src/read/view.html:9–14` and
   `apps/renderer/src/read/dead.html:8–15` define a **non-project** token set
   (`--color-bg:#f8fafc`, `--color-text:#0f172a`, `#475569`, `#fef2f2`, `#991b1b`) instead of the
   mockup `:root` tokens. Phase 5 reuses **only** the mockup token set; no second palette is
   permitted.
2. **CDN / CSP violation (violates FRM-07).** `apps/renderer/src/read/view.html:7` and `:80` load
   FormIO from `https://cdn.form.io/…`. FRM-07 requires `default-src 'self'; script-src 'self'`.
   Phase 5 must load `@formio/js` and its CSS **self-hosted / bundled same-origin** — no CDN
   (`REQUIREMENTS.md` Out-of-Scope also lists "CDN-hosted FormIO bundles").
3. **Admin retry control.** `mockup.html:1573` (admin Submissions drawer) renders a "Retry external
   call" button. That is an **admin** surface; D-81 forbids it on the user status/detail pages.
