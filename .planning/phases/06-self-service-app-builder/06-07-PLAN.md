## Phase Goal

**As a** department admin, **I want to** build, secure, and publish a working app end-to-end, **so that** I need no engineering ticket and no platform admin's help.

<objective>
Deliver the builder SPA's core: the five-step create wizard (BLD-01), the tabbed app editor (BLD-02), the FormIO form designer with 50-action snapshot undo/redo (BLD-04), conditional/validation authoring (FRM-05), the sandbox preview (FRM-09), the visual field-mapping surface (BLD-05), the roles/permission matrix with email autocomplete (BLD-03), the @casl/ability authorization layer (ACL-10, BLD-11), the inline error surface (BLD-07), and the tablet/skeleton responsive layer (BLD-09).

Purpose: this is the surface every earlier plan's API exists for. The SPA holds no token (D-101) — it rides the httpOnly session cookie — and every owner-scoped action compiles against the session middleware's realUserId. The FormIO designer is the phase's integration heart: React 19 and the imperative FormIO builder share one page through the container-as-leaf mount (Pattern 1), and undo/redo is schema-snapshot history (Pattern 2) because FormIO 5.6.1 exposes no builder undo/redo API.

Output: the SPA routes (wizard, editor, designer, roles), the auth/session client, the API client, the builder-ability rule set, and the Playwright specs proving the wizard and designer end-to-end.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → API (SPA) | Owner-scoped actions — the SPA rides the httpOnly session cookie; every request is principal-scoped |
| browser → FormIO SDK | The designer renders owner-authored component schemas |
| browser → identity directory | The role autocomplete queries names/emails |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-SC | Tampering | npm/pip/cargo installs | high | mitigate | No new installs in this plan — @casl/ability was gated and pinned in plan 01; any install added mid-execution re-triggers the legitimacy gate |
| T-06-27 | Spoofing | owner-scoped routes | high | mitigate | Every app-builder route passes through the session middleware's request.user.realUserId and the per-app @casl/ability check; a spec proves a non-owner's PATCH is 403 with the missing-permission name (ACL-09) |
| T-06-28 | Tampering | FormIO schema import | medium | mitigate | The designer saves only schemas authored in the builder — the API validates the schema against the frozen FormIO JSON-schema shape before persisting; the API never executes submitted form logic |
| T-06-29 | Information Disclosure | email autocomplete | medium | mitigate | Autocomplete searches the identity directory by name/email prefix and returns only display fields (name, email) to the requesting owner; the search is rate-limited per the throttler |
| T-06-30 | Denial of Service | FormIO bundle in the SPA | low | accept | @formio/js is code-split per route by Vite; the designer chunk loads on navigation, not on first paint |
</threat_model>
