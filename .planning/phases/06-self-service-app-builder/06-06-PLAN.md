## Phase Goal

**As a** department admin, **I want to** build, secure, and publish a working app end-to-end, **so that** I need no engineering ticket and no platform admin's help.

<objective>
Deliver the connector-request queue (BLD-10, D-97..D-100): the admin self-serves the full connector definition minus the secret, the request lands in a statused `connector_requests` collection, a platform operator fills the credential through the existing audited CLI seam, and the admin flow resumes once provisioned. Plus the submissions viewer and CSV export (BLD-08, D-111) and the data-routing field-mapping endpoint (BLD-05).

Purpose: ROADMAP success criterion 2 — an external/hybrid app is publishable without a platform admin creating the connector. The request shape is exactly the `ConnectorSeed` interface minus the secret value, so the operator's provision step is the existing `ConnectorCredentialsRepository.upsert` call behind the audited CLI seam — no new operator tooling, no relaxed credential gate.

Output: the `connector_requests` collection, repository, service, and endpoints; the operator-side provision extension; the owner-scoped submissions viewer with the visible-column CSV export; the field-mapping endpoint.
</objective>

| builder admin → API (connector requests) | Owner-authored connector definitions — untrusted config entering the connector registry |
