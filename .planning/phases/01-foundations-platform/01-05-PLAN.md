## Phase Goal

> Same derivation as plan 01: the ROADMAP goal is not in user-story format, so it is restated, not invented. **As a** platform engineer, **I want to** have a KMS-shaped key-provider interface and a tested AES-256-GCM envelope with a production guard, **so that** naming the deployment cloud later is a small adapter, not a redesign, and production can never silently fall back to a local key.

<objective>
Ship the secrets mechanism and the guard, not a secret store. Define the `KeyProvider` interface whose
shape must survive the eventual cloud choice, implement a dev-only `LocalKeyProvider` that refuses to
boot in production, implement the versioned AES-256-GCM envelope using Node's stdlib `crypto`, and add
the boot assertion that production without `CRYPTO_KEY_PROVIDER=kms` fails.

Purpose: FND-10 is one of the four irreversible contracts. D-27 is a genuine named blocker — no
deployment cloud has been named — so the interface is the part that must not change later. A guessed
vendor adapter would be untested against a real KMS and would have to be rewritten.

Output: a tested envelope, a dev key provider with a hard production refusal, and a boot guard that
makes silent production fallback impossible.
</objective>
