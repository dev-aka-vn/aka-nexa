<objective>
The one-shot, two-collection, idempotent migration (D-11, corrected: `apps` AND
`app_definition_versions`, never `apps` alone). Every existing app document and every retained
snapshot is rewritten from `form_schema` + app-level `triggers` into the `forms[]` shape 07-01
landed; stored role grants naming the retired `'triggers'` section are dropped; the whole thing
runs as a best-effort boot step in BOTH processes that read app definitions (api and worker),
warns instead of throwing when Mongo is unreachable, and returns a count that is `0` on every
re-run.

Purpose: 07-01 changed the code; this plan changes the data. Without the snapshot half,
`rollback()` (app-definition.service.ts:264-277) would spread a pre-migration snapshot back into
a live doc and silently resurrect `form_schema` + app-level `triggers` while dropping `forms[]` —
a data-corruption path, not a cosmetic one.
Output: `migrateAppForms`, its suite, and two boot wirings.
</objective>
