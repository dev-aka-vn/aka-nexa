  <behavior>
    - Signature `sha256=<hex>` equal to HMAC-SHA256(rawBody, connectorSecret) → accepted.
    - One byte changed in the raw body, or in the hex signature, or a valid signature replayed against a different body → 401.
    - Unknown connectorId, or a connector with no stored secret → 401 (generic message, same shape as a bad signature so the response cannot enumerate valid connectors).
    - A secret whose stored envelope decrypts incorrectly → 401 + structured error log; the secret value appears in neither.
  </behavior>
  <action>Write the failing spec cases first, then implement. (a) Create apps/api/src/webhooks/external/webhook-hmac.service.ts: `verify(connectorId, rawBody, presentedSignature)` — fetch the per-connector secret through `ConnectorCredentialsRepository.get` using a single named credential-ref helper (the `webhook:<connectorId>:hmac-sha256` ref shape; provisioning of the secret itself is packages/cli/provision.ts's job and out of scope here); reject on missing secret; parse the `sha256=<64 hex>` envelope (keep the existing format as a fast-fail before the secret lookup so unauthenticated requests cannot force KMS decrypts); compute HMAC-SHA256 over the **raw request body Buffer** — never over a re-serialized JSON object, because key order and whitespace would make verification nondeterministic and forgeable through re-encoding; compare with `crypto.timingSafeEqual` on two equal-length Buffers, treating a length mismatch as a rejection *without* calling timingSafeEqual (it throws on unequal lengths). Use `import * as crypto from 'crypto'` — the import 08-05 removed from the controller belongs here, where it does real work. (b) Rewrite the controller's step 2: after the nonce/skew gate passes, call the HMAC service; on rejection throw UnauthorizedException with a generic message; on acceptance enqueue a *minimal* job payload — connectorId, the verified body, receivedAt — dropping signature/timestamp/nonce, which downstream logic must never need and which would otherwise ride into job data and logs. Delete the remaining "tracer E2E / foundation" deferral comments (08-VERIFICATION anti-patterns) and the hardcoded-placeholder comments; this endpoint now does what its docblock always claimed. (c) ExternalWebhookModule imports the domain ConnectorsModule (the same wiring path other api modules use to reach domain providers) so the credential repository resolves. Keep nonce/skew ordering as-is: replay gate first, signature second (a forged timestamp must not force a secret lookup either).</action>

| External system → api (`POST /webhooks/external/:connectorId`) | Untrusted webhook; gates are skew window → nonce SET NX EX → per-connector HMAC, in that order |
| Credential store → HMAC compare | Decrypted secret transits memory briefly; must never reach logs, errors, or job payloads |
| Domain lookup chain | External input (entity reference) drives repository queries; unknown input must produce typed outcomes, not exceptions |
