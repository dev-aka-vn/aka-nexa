## Phase Goal

**As a** department admin, **I want to** build, secure, and publish a working app end-to-end, **so that** I need no engineering ticket and no platform admin's help.

<objective>
Close gap G-06-7: the form designer is a navigation dead end. Step 4's only outbound action opens the designer, the designer offers no return affordance, and the only route back is the sidebar's Create app link — which is a FRESH wizard, because every wizard field lives in component-local state.

Nothing that was saved is lost: the draft survives server-side because step 1 POSTs the draft and each later step PATCHes its section. What is lost is the wizard's *position* and any *in-progress* step input, and the user is left with no way to resume the flow they were in.

Purpose: the gap's two `missing` items are DECIDED, not open. The navigation model is *resume the step the user left*, and the wizard must survive the round trip. Because resumption is required, this is a routing/state change rather than a one-control fix: the wizard's position is route-encoded and its in-progress input is snapshotted for the session, and the designer gains a return control that is offered only when there is a live position to resume. A back-to-app-editor breadcrumb is explicitly NOT required and must not be added.

Output: a session-scoped wizard snapshot store with shape guards and an injectable storage, the wizard's hydration plus write-on-change and route sync, the designer's return control, the route's app/step capture, and the e2e round trip the walkthrough could not complete without it.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| designer → wizard (hash route) | A navigation control that must not silently discard the user's position, and must not carry another session's draft |
| browser sessionStorage ↔ wizard | Session-scoped working state written and read by the page, outside the server's control |
| browser → GET a single app | The deep-link fallback fetch crosses into the API and must respect the session's authorization |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-SC | Tampering | npm/pip/cargo installs | high | mitigate | This plan performs NO installs and adds no dependency — it adds two modules in the wizard directory and extends four existing files |
| T-06-46 | Information Disclosure | sessionStorage wizard snapshot | low | accept | The snapshot is session-scoped and same-origin, is cleared when the wizard completes, and holds only the field values the admin is already typing into the SPA — no tokens, no secrets, no server-side user data |
| T-06-47 | Tampering | corrupt or stale snapshot hydrated into the wizard | medium | mitigate | Every read shape-guards the payload and discards anything that is not the expected object with a finite in-range step, then falls back to a fresh or deep-linked wizard; a version field invalidates entries from an older shape |
| T-06-48 | Spoofing | deep link to an app the session may not open | medium | mitigate | The fallback fetch rides the session cookie and the API enforces ownership; a refusal renders the wizard's actionable inline error rather than the draft, so a hand-edited route cannot surface another user's data |
| T-06-49 | Denial of Service | hashchange re-entrancy on the wizard route | low | mitigate | The wizard writes its position with `history.replaceState`, which does not fire `hashchange`, so the page cannot remount itself in a route loop |
