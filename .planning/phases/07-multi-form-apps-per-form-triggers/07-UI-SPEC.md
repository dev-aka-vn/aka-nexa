# Phase 7 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

> **Contract constraints (read first).**
> 1. **`prototypes/mockup.html` is the single source of truth** for layout, information
>    architecture, copy, colour, type and spacing (AGENTS.md "UI Design"). Reuse its `:root`
>    token set verbatim — a colour or typeface not derived from it is a **defect, not a
>    preference** (rule 1).
> 2. **A frozen contract beats the mockup** (rule 2). Where `prototypes/mockup.html` implies a
>    data shape that disagrees with a frozen contract — `packages/contract/src/links/read-link-claims.ts`
>    (D-21 claim set, `form_id`/`form_version`), `packages/contract/src/builder/app-definition.contract.ts`
>    (`SectionNameSchema`, `.strict()` section payloads) — the contract wins and the **mockup is
>    the thing that is wrong**. Say so; never reshape a contract to match a picture.
> 3. **Absence is not permission** (rule 3). The mockup does **not** depict the in-form trigger
>    panel, a kind-picker for "New form", a remove-form confirmation, or a per-form designer for
>    the `list`/`show`/`edit` kinds. Every such gap is listed in
>    [Undepicted Surfaces](#undepicted-surfaces--checkpointhuman-verify) and carries
>    `checkpoint:human-verify` — do **not** improvise a layout for them.
> 4. **Section vocabulary drops 13 → 12**, not 12 → 11. `SectionNameSchema` has **13** entries
>    (`packages/contract/src/builder/app-definition.contract.ts:61-75`); retiring `triggers`
>    leaves 12. Four mirror lists move together: `SectionNameSchema`,
>    `apps/app-builder/src/sections.ts` (`APP_SECTIONS`, `SECTION_LABELS`), both `SECTION_FIELDS`
>    copies, and `APP_SECTION_PERMISSIONS`. Their doc comments already say "twelve" against 13
>    entries — that is pre-existing drift, not permission to publish an 11-count.
> 5. **Phase-7 UI scope:** (a) App Builder `Forms` tab → **form manager** (list / add / remove by
>    kind, launch a per-form designer); (b) the **in-form trigger panel**; (c) **retirement of the
>    app-level `Triggers` tab**; (d) the **13 → 12** editor tabs and permission-matrix rows; (e)
>    whatever **renderer** surface the `list`/`show`/`edit` kinds need (Phases 4/5 already ship
>    `status.html` / `view.html` / `edit.html`, so this is largely re-badging, not new UI).
>    **Out of scope / deferred:** per-form RBAC, per-form visibility, per-form history & rollback,
>    triggers on `show`/`edit`.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, `gap` inside a chip/pill |
| sm | 8px | Compact element spacing (`--od-gap:8px`, stack gaps) |
| md | 16px | Default element spacing, button padding, control height |
| lg | 24px | Section / card padding (`.empty` inner padding, block rhythm) |
| xl | 32px | Layout gaps between columns/regions (`.empty` `padding:32px` in `tabTriggers`) |
| 2xl | 48px | Major section breaks (`.tbl-empty` `padding:48px`) |
| 3xl | 64px | Page-level spacing (`.view` bottom padding `64px`) |

Exceptions — **inherited verbatim from `prototypes/mockup.html` / `chrome.css`; do not re-derive
or "fix" these**, they are already shipped:

- `.btn-sm` `min-height:34px`, `.icon-btn` `40×40px`, `.icon-tile` `38×38px`,
  `.switch .track` `40×23px`, `.radio-card` `padding:13px 15px`, `.list-row` `padding:12px 14px`.
- `.card-head` `padding:16px 18px`, `.card-body` `padding:18px`, `.grid-main`/`.grid-2`/`.grid-3`
  `gap:18px`, `.stack-list` `gap:10px`, `.view` `padding:26px 28px 64px`.
- **Icon-only / label-less touch targets: 44px minimum** (the mockup's `.od-touch`
  `min-width:44px;min-height:44px`).
- New Phase-7 spacing (a new panel's internal rhythm, a new gap) **must** land on the 4/8/16/24/32/48/64
  scale above; the list at the top of this section covers only metrics already in `chrome.css`.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.5 |
| Label | 12.5px | 600 | 1.4 |
| Heading | 16px | 600 | 1.3 |
| Display | 25px | 600 | 1.2 |

**Weights: exactly two — regular (400) and semibold (600).** New Phase-7 surfaces use only
these. `chrome.css` already contains 500/700 in a few inherited places (`.stat .k` 500,
`.error-text` 500, `.step .dot` 700, `.badge` 600); **do not add more.**

**Anchors to shipped values** (so nothing is invented):

- `body` root stays `16px` / `1.55` / `--sans` (`chrome.css:64-72`).
- Display = `.page-head h1` `25px`/`600`/`1.2` (`chrome.css:108`).
- Heading = `.card-head h2` `15.5px` and `.empty h3` `16px` (`chrome.css:143`, `264`) — snap new
  headings to 16px.
- Body = `.list-row .lr-t` `14px`, `.field > label` `13.5px`, `.tab`, `.cell-*` (`chrome.css`).
- Label = `.pill-mono` `12px`, `.helper` / `.lr-s` `12.5px` (`chrome.css`). **Secondary/helper
  text renders at 12.5px weight 400** — the Label size, the lighter weight.
- Headings + display use `--display` (Space Grotesk); body uses `--sans` (IBM Plex Sans); ids,
  versions, JSON and `code-inline` use `--mono` (IBM Plex Mono).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--canvas #f6f8fa` | Page/workspace background |
| Secondary (30%) | `--surface #ffffff` (+ `--surface-2 #f0f3f7`) | Cards, top header, inputs, `card-foot`, `pill-mono`, table header |
| Accent (10%) | `--accent #0f9d8f` (hover `--accent-strong #0b7d72`, tint `--accent-soft #e4f5f2`) | see reserved-for list |
| Destructive | `--red #c0392b` (`--red-soft #fdecea`) | Destructive actions and failure states only |

**Accent reserved for** (exhaustive list — never "all interactive elements"):

1. Primary CTAs — `.btn-primary` (`New form`, `Save form`, publish/save confirm).
2. The **active** editor tab — `.tab[aria-selected="true"]` bottom border + text.
3. Focus rings — `:focus-visible` outline and `.input:focus` / `.search input:focus` glow.
4. Selected `radio-card` (`.sel`) and checked `.switch .track`.
5. `.callout-accent` — the sanctioned accent note (mockup: "All forms are rendered by FormIO.js").
6. `.meter span` fill and the active `.step.now .dot`.
7. `a { color: --accent-strong }` link text.

**Semantic scales are status, not decoration:**

- `--green #2f855a` — published / completed.
- `--amber #b7791f` — draft/attention, `partial`, deprecated, `callout-warn`.
- `--blue #2b6cb0` — `pending_external`, `callout-info`.
- `--violet #6b5bd2` — archived.
- `--red #c0392b` — destructive / `failed` / `callout-danger` / `.invalid`.

Never introduce a colour or typeface outside these tokens (AGENTS.md rule 1).

## Copywriting Contract

Source precedence: **mockup verbatim first**; rows marked *(proposed)* are **undepicted** in
`prototypes/mockup.html` and require `checkpoint:human-verify` — see
[Undepicted Surfaces](#undepicted-surfaces--checkpointhuman-verify).

| Element | Copy |
|---------|------|
| Primary CTA | `New form` — Forms tab header, mockup `open-builder` button (`icon("i-plus") + "New form"`). Designer CTA: `Save form`. Trigger-panel CTA: `Add trigger` (mockup `add-trigger`). |
| Empty state heading | `No triggers yet` — mockup `tabTriggers` verbatim, relocated into the in-form trigger panel (D-12). |
| Empty state body | `Add an intent or slash command so users can launch this app from chat.` — mockup verbatim. |
| Empty state — forms manager | *(proposed)* No empty list is rendered: `submit` is mandatory (D-05), so the manager always shows ≥1 form. Before load it shows `Skeleton` (BLD-09), not an empty state. |
| Error state — section save (BLD-07) | Inline `InlineError`: the rejected field is named, nothing is published. Shape: `Couldn't save this section. "<field>" is not allowed on section "<section>". Nothing was published.` |
| Error state — publish gate (SC#2) | *(proposed)* `Publish blocked: a trigger resolves to more than one form. Each trigger activates exactly one form. Edit the trigger and publish again.` |
| Error state — renderer links | Reuse the shipped `DENY_REASON_COPY` map in `apps/renderer/src/read/view.ts` (expired / consumed / revoked / not_owned / denied / bad_signature …). **Do not author new strings.** |
| Destructive confirmation — remove form | *(proposed)* `Remove form` modal (`btn-danger`): `Remove "‹form label›"? This removes the form and its trigger. Submissions already created through it keep their data. This can't be undone from here.` |
| Destructive confirmation — remove trigger | Mockup's `icon-btn` remove (`aria-label="Remove trigger"`) acts **without** a modal, matching the shipped pattern. |

**Trigger row vocabulary (mockup + `TriggersStep.tsx`, reuse verbatim):**

- Row title: `Intent · {intent}` or `Slash command · {command}`.
- Row sub-line: `Examples: {ex1} · {ex2}` (intent) or `Deterministic routing — bypasses JEV (no-JEV mode).` (slash).
- Input placeholders: `Intent label, e.g. request_leave`, `Example phrase, e.g. I want to take leave`, `Slash command, e.g. /leave request`.
- Helper: `Only triggers for the requesting user are sent to the JEV decision engine. Intents match on example phrases; slash commands route deterministically.`
- Side-card helper (mockup `tabTriggers` JEV behavior): `Below threshold → clarification prompt or fall back to rule-based.`

**Form-manager row vocabulary (mockup `tabForms`, reuse verbatim):**

- Row title: `{form label}` (e.g. `Create leave`).
- Row sub-line (mono): `{id} · {action} · requires {perm}` (e.g. `create-leave · create · requires leave:create`).
- Version pill: `v{version}`.
- Row action: `Preview` (`icon("i-eye")`).
- Header: `Forms` + `New form`. Side card: `Versioning` with `Published form changes never affect in-progress submissions. The form version is pinned at link creation.` and rows `v{n} · current` / `v{n} · archived`.
- Accent callout: `All forms are rendered by **FormIO.js** — the single permitted engine for both the drag-and-drop builder and the runtime renderer.`

Per `AGENTS.md` rule 3, these are **gaps in the mockup, not licence to improvise**. Each must be
confirmed with the user before implementation. The sanctioned source material for all of them is

D-03 makes `show` a **config over the `submit` schema** (which fields, ordering, read-only derived fields) and D-04 makes `list` a **saved-query reference + column config** — neither is drag-and-drop, and neither is depicted. | Layout and controls for both config surfaces; confirm `show` is field-selection/ordering over the `submit` schema and `list` is query-reference + column config. |
